# Ash v0.1 实现决策

日期：2026-09-05。

本文件记录实际实现。`architecture.md` 保留目标架构；下面的分期决定优先于把目标设计误读为已经实现的能力。

## 已采用的架构

SwiftUI / AppKit 客户端 + SwiftTerm 1.20.0 + Rust 主机运行程序 + OpenSSH + tmux + SQLite。

客户端终端使用 SwiftTerm 的 LocalProcessTerminalView 启动 tmux attach 或 ssh attach。实际 Shell / Agent 由 tmux 托管。显示进程退出不终止被托管进程。

同一个 Rust 可执行程序支持 `request`、`worker`、`execute` 三种内部角色。它们复用领域模型和数据库：

- request：读取一个 stdin JSON 请求并写出一个 JSON envelope，可通过 SSH 直接承载。
- worker：在专属 tmux scheduler 会话中调度队列，独立于 GUI 和 SSH 通道。
- execute：在每个 tmux 会话内监督本次 Shell / CLI Agent，记录退出结果。

首版没有再引入一套 launchd/systemd 注册流程。tmux 服务和 scheduler 共同承担用户会话内的后台运行；它们不提供主机重启后的进程复活。调度器存在但停止时，后续请求负责重启；排队任务会在恢复后继续。

## 控制协议

首版采用单请求进程协议而非长期 socket 和流式事件：

```json
{"protocol":1,"action":"health"}
```

响应：

```json
{"ok":true,"data":{"protocol":1,"version":"0.1.0"}}
```

错误使用 `{"ok":false,"error":"..."}`。请求上限 1 MiB。真实 health 响应还包含平台、tmux、数据目录、Agent 路径和并发限制。

支持动作：health、list、start、cancel、archive、changes、worktree、settings、transcript。终端数据走独立 PTY，不使用 JSON 包装。

SQLite 每次状态变更与事件在同一事务中记录，文件锁串行化启动和 Git worktree 操作。客户端每三秒获取快照，连接错误保留最后状态。事件游标订阅、历史剪裁和推送不在首版协议中。

| 真实交互 CLI | 是 | 是 | 是 |

| 排队、取消、重试 | 是 | 是 | 是 |

| Provider 对话恢复协议 | 未接入 | 未接入 | 未接入 |

恢复同一个仍存活的进程与重试新进程不同。重试保留 Task ID 并创建新的 Run ID，不冒充 Provider 的会话恢复。Agent 退出后显示“已退出 · 待检查”，不会自动将用户目标设为完成。

## Git 与结果

worktree 在当前执行主机的 Ash 数据目录创建，使用 `ash/<workspace-id>` 分支。以当前 HEAD 为基准，不自动携带脏 checkout 的改动。当前未实现 setup 脚本执行，因此不会自动运行从仓库读取的工作区初始化命令。

Git diff 禁用外部 diff 和 textconv，预览限制为约 200 KB。单独列出未跟踪文件。终端导出使用 tmux 最近至多约 2000 行或退出时保存的文本；tmux 历史限制 20000 行。它不是完整的 ANSI 录屏回放或无限持久日志。

## 远端发布

应用中包含运行程序源码、Cargo.lock 和安装脚本。用户发起安装时，通过现有 SSH 认证向远端传输这些固定内容，远端使用已有 Cargo 构建。首次接入仍需要在远端准备系统构建依赖；当前没有发布可验证下载的跨平台预编译二进制。

## 待后续演进

目标架构中的长期控制通道、版本化事件订阅、平台服务注册、Provider 事件适配器、可恢复工作区删除事务、端口管理、自动化与完整发布签名，留待后续版本。

这些扩展沿用现有 Host / Workspace / Task / Run / Session 边界，不需要把工作区逻辑重新绑定到窗口。
